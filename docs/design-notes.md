# 설계 노트 — 코드 주석의 「설계 §n」이 가리키는 결정 요약

정본: `docs/superpowers/specs/2026-09-20-matjangbu-design.md`(설계) · `docs/superpowers/plans/2026-09-20-matjangbu.md`(계획).

| 결정 | 내용 | 이유 |
|---|---|---|
| 모델은 한 칸 | 규칙 2단이 못 푼 줄만 모델이 보고, 결과는 항상 `held` | 1.5B 모델은 틀린다(첫 기록에서 「우리상사」를 가족 명의로 찍었다). 확정을 사람에게 두면 모델이 틀려도 장부가 틀리지 않는다 |
| 동명이인 자동 확정 금지 | 명부에 같은 이름이 둘이면 모델도 안 거치고 `held/dup`, 새 이름 등록 없음 | 오매칭의 대가가 가장 큰 경우 |
| 세대주 규칙 | 명부 세대 칸에 세대주 이름을 적어 두면 그 이름의 입금은 규칙으로 가족 후보 | 가족 명의 이체를 모델 없이 푸는 유일한 결정론 경로 |
| 모델이 낸 종류는 원문 검사 | `kind`는 원문에 그 글자가 있을 때만 받는다 | 첫 기록에서 모델이 「감사」를 지어냈다 |
| append-only 대장 | `lines.jsonl`은 덧붙이기만, 되돌리기도 새 줄(`undo_of`) | 나비 store.py 규칙 — 이력이 지워지지 않는다 |
| 별칭 사전은 확정에서만 | 원문 ≠ 이름일 때만 적립, 먼저 배운 것이 남음, 되돌리면 잊음 | 자동 확정된 줄은 별칭이 아니다 |
| 체험 = 실제 파이프라인 + 모델 재생 | 샘플 CSV 를 실제 규칙으로 돌리고 모델만 `recorded.json`에서 재생 | 방문자가 W10 에서 확정한 별칭이 W11 에서 실제로 작동해야 「다음 주부터 자동」이 거짓말이 아니다 |
| 삼중 폴백 | 같은 origin → meta 인스턴스 → recorded.json 읽기 전용 | 인스턴스는 집 노트북이라 죽을 수 있다. 링크는 살아 있어야 한다 |
| 기본 모델 Qwen2.5-1.5B | HyperCLOVAX-SEED 는 이 폰에서 한국어가 더 자연스러웠지만 라이선스가 자체 약관 | 공개 저장소·배포 문구에 Apache-2.0 만 |
| 포트 8107/8108 · 벤치 8117 | 나비(8097/8098)와 한 기기에서 겹치지 않게 | — |
| 가격 없음 | 신청서의 월 5만 원은 인터뷰 1건 | 재지 않은 숫자는 적지 않는다 |
| 프롬프트에 판정 규칙·예시 3개 | 상호→company, 성만 같으면 unknown, 이력 있으면 1순위 | 규칙 없이 돌린 첫 기록은 relation 이 전부 family 였다 |
| /try 만 React + shadcn | 상호작용이 있는 장만 React, 랜딩·설치·기기는 순수 HTML 에 같은 토큰 | 랜딩은 인스턴스가 죽어도 살아야 한다. 정본 `docs/superpowers/specs/2026-09-21-ui-toss-redesign-design.md` |
| 그라데이션 3종 = 세 경로 | 청록→초록 규칙·자동(주색), 파랑→보라 모델, 초록→노랑 사람. 5종류 요소에만, 면에는 금지 | 색이 곧 설명이 된다. 「확인 필요」는 앰버 단색 |
